# moonshine-dictate 要件定義（第1版）

Windows 11 の音声入力（Win+H）と同じ操作で使える、完全オフラインの日本語音声入力ツールを作る。音声認識には Moonshine Voice と日本語モデルを使い、モデルはアプリに同梱して配布する。

各要件には番号を振り、議論や Issue ではこの番号で参照する。「要確認」と書いた項目は、実装前に実機かドキュメントで確かめる。

## 1. 対象 OS とサポート範囲を決める

| OS | サポート範囲 |
| --- | --- |
| Windows 10 / 11（x64） | 全機能 |
| macOS 13 以降（Apple Silicon のみ。moonshine-voice の Intel Mac 向けパッケージが 0.0.59 で止まっているため） | 全機能。ただし署名・公証なしで配布する（1.3） |
| Linux（X11） | 全機能 |
| Linux（Wayland） | 制限付き（1.2） |

- **R1.1** 動作確認の基準環境は Windows 11、macOS 14、Ubuntu 24.04（GNOME）の3つとする。
- **R1.2** Wayland では次の制限を認め、README に明記する。
  - 第1版ではグローバルホットキーを登録しない。利用者が OS のショートカット設定に `moonshine-dictate toggle` コマンドを割り当てる（R3.4）。XDG Desktop Portal の GlobalShortcuts を使った登録は第2版以降で検討する。
  - テキストは `wl-copy` でクリップボードに入れ、貼り付けキーを `ydotool` で送る。`ydotool` が使えない環境では、クリップボードに入れたことを通知し、貼り付けは利用者が行う。
  - ライブ入力（R5.3）は Wayland では使えない。
  - 録音ウィンドウ（R4）の表示位置と最前面表示は保証しない。
- **R1.3** macOS 版は Apple Developer Program に加入せず、アドホック署名だけで配布する。そのため次の点を README に書く。
  - 初回起動時は Gatekeeper の警告が出るので、Finder で右クリックして「開く」を選ぶ。
  - 「マイク」と「アクセシビリティ」の許可が要る。アップデートするとアクセシビリティの許可が外れる場合があり、そのときは一度削除して付け直す（要確認：アドホック署名でどの程度外れるか）。
- **R1.4** Windows 版もコード署名をせずに配布する。スマート アプリ コントロールがオンの PC では、署名のない実行ファイルや DLL が止められることがある（2026年11月、Windows 11 の実機で `pip.exe` と `moonshine.dll` が「アプリケーション制御ポリシーによってこのファイルがブロックされました」〔WinError 4551〕で止められた。`moonshine.dll` は2回目の実行で読み込めた）。回避方法と制限を README に書く。止められる利用者が多い場合は、Azure Trusted Signing などでの署名を検討し直す。

## 2. 音声をローカルで認識する

- **R2.1** 音声認識は Moonshine Voice と日本語モデルで行い、CPU だけで動かす。GPU は使わない。
- **R2.2** モデルはインストーラーまたはアプリ本体に同梱し、初回起動時のダウンロードは行わない。
- **R2.3** アプリはネットワーク通信を一切しない。アップデート確認、利用統計の送信、クラッシュレポートの送信も行わない。
- **R2.4** 発話は無音検出（VAD）で区切り、区切りごとに認識する。録音が長くなっても、終了時に全体をまとめて認識する待ち時間が発生しないようにする。
- **R2.5** 同梱するモデルは日本語のストリーミング版 `small-streaming-ja`（量子化版、122MB）とする。moonshine-voice 0.1.6 が日本語で標準に使うモデルである。R2.6 の性能目標を満たせない場合は `tiny-streaming-ja`（量子化版、32MB）に切り替える。日本語のモデルは次の4種類がある（moonshine-voice 0.1.6 のモデル一覧から取得）。

| モデル | ストリーミング | ファイルサイズ |
| --- | --- | --- |
| `small-streaming-ja`（標準） | 対応 | 122MB |
| `tiny-streaming-ja` | 対応 | 32MB |
| `base-ja` | 非対応 | 141MB |
| `tiny-ja` | 非対応 | 72MB |

  - Medium Streaming は英語にしかない（moonshine-voice 0.1.6 で確認）。
  - 2026年11月、Windows 11 の実機で small-streaming-ja の精度が低く、使えないと判断された。同じ録音を各モデルにかける `scripts/compare_models.py` で small-streaming と base を比べ、同梱するモデルを決め直す。設定項目 `model_arch` で base も選べるようにした。
- **R2.6** 性能目標：1区切り（10秒以内の発話）が終わってから、その区切りのテキストが挿入されるまで1秒以内とする。基準機は Core i5 第10世代相当、または Apple M1 とする。
- **R2.7** ストリーミング認識の途中結果は `LineTextChanged` イベント、区切りの確定は `LineCompleted` イベントで受け取る。録音ウィンドウの途中表示（R4.4）には前者を、ライブ入力（R5.3）には後者を使う。

## 3. ホットキーで録音を開始・終了する

操作は Windows の音声入力に合わせ、1回押すと開始、もう1回押すと終了するトグル方式にする。押している間だけ録音する方式は作らない。

- **R3.1** ホットキーを押すと、フォーカスの位置に関係なく必ず録音を開始する。テキスト欄にフォーカスがあるかどうかは判定しない。
- **R3.2** 録音は次のどれか1つが起きた時点で終了する。
  1. もう一度ホットキーを押す。
  2. 録音ウィンドウのマイクボタンを押す（R4.2）。
  3. 無音が60秒続く。秒数は設定で変えられる（R6）。
- **R3.3** 標準のホットキーは、Windows と Linux では Ctrl+Alt+Space、macOS では Control+Option+Space とし、設定で変えられる。Win+H は Windows 標準の音声入力が使っているため使わない。
- **R3.4** 常駐プロセスへの指示用に、コマンド `moonshine-dictate toggle`、`start`、`stop` を用意する。Wayland のホットキー（R1.2）と、他のツールからの呼び出しに使う。

## 4. 録音中は画面に録音ウィンドウを出す

- **R4.1** 録音を開始すると、画面下部の中央に小さなウィンドウを出す。ウィンドウにはマイクボタンを置き、録音中は点灯させる。録音が終わったらウィンドウを閉じる。
- **R4.2** マイクボタンを押すと録音を終了する。
- **R4.3** 録音ウィンドウは常に最前面に表示し、表示したときもクリックしたときもフォーカスを奪わない。フォーカスを奪うと、テキストが元のアプリではなく録音ウィンドウに入ってしまうからである。実装方法は Windows が `WS_EX_NOACTIVATE`、macOS が非アクティブ化の `NSPanel` を想定する。Linux（X11）での方法は要確認。
- **R4.4** 録音ウィンドウには、認識中の途中結果を表示する。挿入先のアプリには、確定したテキストだけを入れる。
- **R4.5** 録音の開始時と終了時に短い効果音を鳴らす。設定で無効にできる。
- **R4.6** 常駐中はタスクトレイ（macOS ではメニューバー）にアイコンを出す。録音中はアイコンを変える。メニューには「録音開始／終了」「設定ファイルを開く」「設定の再読み込み」「終了」を置く。

## 5. 認識したテキストを2つの方法で挿入する

挿入方法は設定で選ぶ。どちらの方法でも、挿入先は挿入する時点でフォーカスがあるウィンドウとする。

- **R5.1** 方法1「クリップボード」：録音終了時に、確定したテキスト全体を一度に挿入する。テキストをクリップボードに入れて貼り付けキー（Ctrl+V、macOS では Cmd+V）を送る。
- **R5.2** クリップボード方式では、貼り付けの後に元のクリップボードの内容を戻す。戻す処理は設定で無効にできる。戻せる形式はテキストに限る（画像などは要確認）。
- **R5.3** 方法2「ライブ入力」：区切りが確定するたびに、そのテキストを入れる。Windows と Linux（X11）では、区切りごとにクリップボード経由で貼り付ける。macOS では `CGEventKeyboardSetUnicodeString` で Unicode のキー入力として送る。Windows と Linux でキー入力を使わないのは、日本語が化けたためである。
  - Windows（`SendInput` の `KEYEVENTF_UNICODE`）：日本語 IME がオンのとき、「もう次に進んでも大丈夫ですよ」が「もうんでもですよ大丈夫次進」になった（2026年11月、Windows 11 の実機）。
  - Linux（XTest）：Xvfb 上の Qt アプリで「こんにちは、世界。」が「こんんちはは世界界」になり、1文字ごとに30ミリ秒の間を空けても直らなかった。
- **R5.4** ライブ入力では、一度挿入したテキストを後から消して直す処理は行わない。途中結果は録音ウィンドウにだけ表示する（R4.4）。
- **R5.5** ライブ入力で、日本語 IME がオンのままでも文字が正しく入るかを確認する。Windows はキー入力では入らなかったため、貼り付けに変えた（R5.3）。macOS は要確認。
- **R5.6** 標準の挿入方法はクリップボードとする。ライブ入力は、文字の欠けや順序の入れ替わりがアプリによって起きる可能性があるからである。

## 6. 設定を TOML ファイルに持たせる

- **R6.1** 設定ファイルは TOML 形式とし、各項目の説明をファイル内のコメントに書く。
- **R6.2** 設定ファイルの置き場所は次のとおりとする。初回起動時に、標準値を書き込んだファイルを作る。
  - Windows：`%APPDATA%\moonshine-dictate\config.toml`
  - macOS：`~/Library/Application Support/moonshine-dictate/config.toml`
  - Linux：`$XDG_CONFIG_HOME/moonshine-dictate/config.toml`（未設定なら `~/.config/moonshine-dictate/config.toml`）
- **R6.3** 設定画面は作らない。トレイメニューの「設定の再読み込み」で、アプリを再起動せずに反映する。
- **R6.4** 設定ファイルに誤りがある場合は、誤った項目名と値を通知に表示し、その項目だけ標準値で動かす。TOML の書式の誤りでファイル全体を読めない場合は、行番号を表示し、すべての項目を標準値で動かす。
- **R6.5** 第1版の設定項目は次のとおりとする。

| 項目 | 内容 | 標準値 |
| --- | --- | --- |
| `hotkey` | 録音の開始・終了キー | `ctrl+alt+space`（macOS は `ctrl+option+space`） |
| `silence_timeout_sec` | 無音がこの秒数続いたら終了する | `60` |
| `insert_method` | `clipboard` または `live` | `clipboard` |
| `restore_clipboard` | 貼り付け後に元のクリップボードに戻す | `true` |
| `input_device` | マイクのデバイス名。空なら OS の既定 | `""` |
| `sound` | 開始・終了の効果音 | `true` |
| `autostart` | OS へのログイン時に起動する | `false` |
| `log_level` | `error` / `info` / `debug` | `info` |
| `[replace]` | 認識結果の置換表（例：`"でぃすこーど" = "Discord"`） | 空 |

## 7. 配布物とライセンスを整える

- **R7.1** 配布形式は Windows がインストーラー（`.exe`、Inno Setup で作る）、macOS が `.dmg`（Apple Silicon 版のみ）、Linux が AppImage とする。配布物は GitHub Actions で作る。モデルなしでの大きさは、Linux 版の展開後が 255MB、AppImage が 94MB だった（2026年11月、PySide6 6.12）。
- **R7.2** 配布物には Moonshine Community License の全文を同梱する。再配布の条件はライセンス本文で確認する（要確認）。moonshine-voice 0.1.6 は、英語以外のモデルを読み込むときに「non-commercial Moonshine Community License」と表示する。README では「年間収益100万ドル未満なら商用も可」と書いているので、どちらが正しいかを https://www.moonshine.ai/license で確かめ、README を合わせる。
- **R7.3** README の「公式ライセンス全文」のリンクを https://www.moonshine.ai/license に直した。

## 8. Python と PySide6 で実装する

- **R8.1** 言語は Python 3.12 以降、画面は PySide6（Qt）で作る。音声認識は公式の Python パッケージ `moonshine-voice` を使う。0.1.6 の時点でパッケージ本体は 22MB で、ONNX Runtime を含むネイティブライブラリ（Linux 版で 13MB）が入っている。録音には同梱の `sounddevice` を使う。
- **R8.2** グローバルホットキーとキー送信には pynput を使う。録音ウィンドウのフォーカス制御は、Windows は ctypes、macOS は pyobjc で直接設定する。クリップボードの読み書きは Qt で行う。
- **R8.3** 配布物は PyInstaller で作る。ウイルス対策ソフトの誤検出が問題になったら Nuitka に切り替える。
- **R8.4** `moonshine-voice` は互換性のない API の変更が入ることがあるため、バージョンを固定する。

- 設定画面
- 日本語以外のモデルへの切り替え
- GPU での認識
- Wayland でのライブ入力
